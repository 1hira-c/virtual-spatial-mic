# Virtual Spatial Mic

**Virtual Spatial Mic (VSM)** は、外部マイクの音をVRChat内のアバターの口元に配置し、撮影カメラの位置で収音したような立体音声を生成する非公式ツールです。

単体アプリで音声を録音でき、VRChatカメラのSpout映像と処理済み音声をMP4動画にまとめて録る試作機能もあります。処理済み音声をOBSへリアルタイムに渡すことや、原音と位置情報を保存して後から処理し直すこともできます。

VSM 0.2.0です。Windows x64・VRChat（VR／デスクトップモード）・口追跡モジュールを導入したアバターを対象としています。モジュールは独立して版を管理し、0.2.0-previewとの組み合わせで動作確認しています。0.1.0のOBSプラグインは廃止しました。[変更履歴と既知の問題](CHANGELOG.md)を参照してください。
## 使い方

1. アバターに口追跡モジュール（以下、モジュール）を追加します。
2. VRChatでそのアバターを使い、OSCをONにしてカメラを開きます。
3. 単体版の **「音のみ」** タブでマイクを選び、追跡状態と音声を確認します。
4. 音だけなら録音を開始します。単体で動画も録る場合は、VSMの「OBS連携」をOFF、VRChatのSpout出力をONにし、**「録画」** タブで映像を選んで録画を開始します。保存した収録は **「ライブラリ」** タブから確認できます。OBSと一緒に使う場合は、単体版の出力をOBSの音声ソースで取り込み、OBSの録画開始・停止に音声保存を連動させます。

[導入から最初の録音まで](docs/getting-started.md) / [OBSで使う](docs/obs-live.md) / [モジュールの導入](integrations/unity/README.md) / [ソースからビルドする](docs/development.md)

モジュールはModular Avatarで非破壊に追加できます。同期パラメーターの消費は0 bitです。口元の位置合わせはアバターへの導入時に一度行います。録音ごとにカメラを口元へ寄せる校正は不要です。

## VRChatの「Audio from Camera」との違い

VRChat内のワールド音や他の人の声をカメラ位置から聴く用途には、標準のAudio from Cameraが使えます。VSMが扱うのは、外部マイクなどから入ってくる音です。

OBSだけでは分からないアバターの口元とカメラの位置関係を使い、演者の声を空間化します。単体版の動画にも、この処理済みマイク音声だけが入ります。VRChatのワールド音・他の人の声・Windowsのシステム音は、現段階ではVSMの収録対象に含みません。

## 保存と再処理

原音保存は初期状態で有効です。原音・位置・時刻情報を残すことで、VRChatを終了した後にも音声を再処理できます。元の音声は上書きしません。再処理は、録画時の出力とのサンプル単位の一致を保証するものではありません。

単体版の動画は、同じ録音フォルダーの `video.mp4` に保存します。映像は30 fps・H.264、音声はAACステレオです。MP4は録画開始ボタンを押した時点から収録し、プリロールは含めません。音声単体のWAVには従来どおりプリロールを保存します。**「ライブラリ」** タブの **「動画」** から再生できます。

## 必要なものと制限

- Windows x64、音声入力、ヘッドホンまたはイヤホン
- VRChatと、モジュールを導入したアバター
- 単体で動画も録る場合はVRChatのSpout出力（OBS・FFmpeg・Spout SDKのDLLは不要）
- OBSで録画する場合はOBS Studio 28以降（VSM用プラグインは不要）
- 単体版の実行にはWebView2 Runtime

初版は1音源・1カメラを対象とします。Linuxは対応対象外です。デスクトップモードでも実機動作を確認しており、カメラを使った上半身トラッキングとの併用も利用者による動作確認があります。近接効果の専用処理は未実装です。長時間の安定性、映像との同期、状態変更をまたぐ追従は引き続き検証しています。

単体動画録画は新しく追加した試作機能で、VRChat実機での録画はまだ検証していません。映像との同期・色・長時間録画は確認中です。

モニター出力の処理済み音声は取得時刻から300 ms後に出力するよう予定します。OBSで映像と合わせる場合は、映像側の遅延を収録環境で調整してください。

Windowsでは入力を有効にした際、ファイアウォールの通信許可ダイアログが表示される場合があります。音声・位置データの受信とOSCQueryのHTTP受付はlocalhostですが、サービス発見用のmDNS広告はネットワークインターフェースから送信します。この表示の解消は未完了です。

## 開発とライセンス

製品はRust/Tauriで構成し、`cargo` でビルドできます。空間処理にはRustで書かれた [sofar](https://github.com/andreiltd/sofar) と、SADIE II DatabaseのHRTFデータを使います。Spout受信は公式実装を参考にRustで実装し、MP4の生成にはWindowsのMedia Foundationを使います。[ビルド手順と構成](docs/development.md)、[依存物とライセンス](docs/dependencies.md)を参照してください。
